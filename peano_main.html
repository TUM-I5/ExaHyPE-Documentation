The generated main routine

The generated main is a small adapter between an application's repositories and runner::launch(). It registers the algorithmic steps and lets the runner own initialisation, phase ordering, rank coordination, reporting, and shutdown.

Registered steps

Each generated observer becomes one runner::Step. Its body follows this lifecycle:

observers::TimeStep::prepareTraversal();
observers::TimeStep observer;
peano4::topology::TopologyManager::getInstance().traverse(observer);
observers::TimeStep::unprepareTraversal();

prepareTraversal() and unprepareTraversal() run once per rank and step. The topology manager creates the observer clones required by the rank traversal and its subtree tasks. The call returns after all clones finish and the rank-boundary payloads for that sweep have been submitted.

The generated StepRepository maps each generated step enumeration to the integer program-step identifier distributed by runner::RunControl. Every rank registers the same ordered step list.

Launch

The generated entry point has the following shape:

int main(int argc, char** argv) {
runner::RuntimeParameters::getInstance().setGeneratedDefaults(
minimumTerminalTime,
maximumTerminalTime,
gridLevels,
maximumGridLevels,
projectName
);
return runner::launch(
DomainOffset,
DomainSize,
PeriodicBC,
createRepositoryCallbacks(),
createSteps(),
argc,
argv
);
}

runner::launch() configures the runtime parameters, initialises tarch and Peano, constructs runner::Engine, and performs the matching shutdown sequence. The repository callbacks connect application-specific parameter loading, memory accounting, help text, and repository shutdown to this lifecycle.

SPMD control flow

runner::Engine gives the global master to runner::Orchestrator. The orchestrator runs configuration, grid construction, grid initialisation, time loop, dynamic AMR, and final reporting phases as required by the registered steps. Before each step, the master publishes its program-step identifier. Worker ranks receive the identifier through runner::RunControl::continueToRun() and execute the same registered body. The terminate identifier ends every worker loop.

A step therefore has one collective ordering across the MPI ranks. Custom work outside the registered body must preserve that ordering whenever it uses MPI or mesh-bound data.

Python API

The Python API builds the step list from the project's solver steps. It emits the observers and repositories and assigns stable enumerators through StepRepository. Application code normally adds action sets and callbacks to these generated steps.
