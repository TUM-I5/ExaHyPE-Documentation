NCC

We recommend using gpu10, gpu11 or gpu12, i.e. the A100 machines. These cards have compute capability 8.0, so the GPU architecture is sm_80 throughout. Peano builds with CMake; the ExaHyPE 2 extension is always built, so you only toggle the PEANO_WITH_* feature options. NVC++ and the oneAPI software stack both work on this cluster.

OpenMP offloading with Clang

module load nsight-systems cuda llvm
module load mvapich2/2.3.5-2
mkdir build
cd build
cmake .. -DCMAKE_BUILD_TYPE=Release \
-DCMAKE_CXX_COMPILER=clang++ \
-DPEANO_WITH_GPU_BACKEND=ompt \
-DPEANO_WITH_GPU_ARCH=sm_80
make -j

The ompt backend drives OpenMP target offloading. CMake adds the matching -fopenmp-targets=nvptx64-nvidia-cuda --offload-arch=sm_80 flags for you.

OpenMP offloading with NVC++

On the A100 nodes you can also use the NVIDIA HPC compiler:

mkdir build
cd build
cmake .. -DCMAKE_BUILD_TYPE=Release \
-DCMAKE_CXX_COMPILER=nvc++ \
-DCMAKE_C_COMPILER=nvc \
-DPEANO_WITH_GPU_BACKEND=ompt \
-DPEANO_WITH_GPU_ARCH=sm_80
make -j

CMake translates sm_80 into the NVHPC -mp=gpu -gpu=cc80 flags automatically.

Some nodes (e.g. gpu3) have Titan XP which doesn't support OpenMP offloading; only GPUs with compute capability >=70 can offload with OpenMP. You can check the GPU model with nvidia-smi -L.

If runs crash with a complaint about a lack of visible devices, set the following environment before you start your experiments:

export CUDA_VISIBLE_DEVICES=0

SYCL offloading with oneAPI

For Intel GPUs the oneAPI/icpx stack maps onto the native backend with the spir64 architecture:

source /opt/intel/oneapi/setvars.sh
mkdir build
cd build
cmake .. -DCMAKE_BUILD_TYPE=Release \
-DCMAKE_CXX_COMPILER=icpx \
-DCMAKE_C_COMPILER=icx \
-DPEANO_WITH_GPU_BACKEND=native \
-DPEANO_WITH_GPU_ARCH=spir64
make -j

CMake emits the required -fsycl -fsycl-targets=spir64 flags for you. icpx uses a lower floating-point precision by default in favour of performance; pass -DPEANO_EXTRA_CXX_FLAGS=-fp-model=precise if you need stricter semantics.

To target the A100 cards through SYCL instead, use the AdaptiveCpp backend, which compiles SYCL down to CUDA:

module load cuda
mkdir build
cd build
cmake .. -DCMAKE_BUILD_TYPE=Release \
-DPEANO_WITH_GPU_BACKEND=acpp \
-DPEANO_WITH_GPU_ARCH=sm_80
make -j

CMake sets the AdaptiveCpp target cuda:sm_80 from PEANO_WITH_GPU_ARCH.

When running the executable on the GPU, include SYCL_DEVICE_FILTER=gpu before the terminal command to explicitly tell SYCL to run the code on the GPU. In the case of a runtime error, it is also useful to add SYCL_PI_TRACE=2 to check where the error was raised.
