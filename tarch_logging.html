Logging And Assertion Architecture

Peano is built upon a technical architecture (tarch) which provides logging and assertions. The relevant files are tarch/instrumentation/Log.h, the level specific macro headers Debug.h, Info.h, Warning.h and Error.h, tarch/instrumentation/CommandLineSink.h, tarch/instrumentation/FileSink.h, tarch/instrumentation/Watch.h, tarch/instrumentation/Measurement.h and Assertions.h.

When we build Peano, diagnostics are controlled by two independent compile-time switches:

  • If a code is translated with -DPEANO_ASSERTIONS=0 and -DPEANO_DEBUG=0, debug logging and assertion macros are disabled, i.e. replaced by empty statements. Warnings, information and error messages are still displayed.
  • If a code is translated with -DPEANO_ASSERTIONS=1, Peano's assertions are enabled, i.e. assertion macros do not degenerate to nop but actually run tests. This might increase the runtime significantly as tests run permanently.
  • If a code is translated with -DPEANO_DEBUG=1, debug-only data, consistency checks and debug messages are compiled in. Debug messages are still filtered at runtime before the message is constructed. This avoids unbounded file and terminal output in full simulation runs.

Using The Logging Interface

Peano relies on a plain interface to write out user information. All constituents of this interface are collected in the package tarch::instrumentation. The usage paradigm is simple:

  1. Logging macros can be used directly. They derive the scope label from the compiler function signature at the call site, including namespace and class information when the function is implemented in a namespace or class.
  2. The macro argument is a stream expression.

Peano offers user facing logging macros:

  • Info. Should be used to inform your user about the application's state.
  • Warning. Should be used to inform your user about suspicious behaviour. The MPI code uses it, e.g., if many messages arrive in a different order than expected. Messages written to the warning level are piped to cerr and highlighted in yellow on interactive terminals.
  • Error. Should be used for errors. It is piped to cerr and highlighted in bold red on interactive terminals. logError(...) does not terminate the process.
  • Debug. Should be used to write debug data. All debug data is removed unless you translate with PEANO_DEBUG. Debug messages are runtime filtered before the message is constructed. If enabled, they are written to the file dump and stdout.

Logging Devices, Formats, Backends And Profiling Support

The logging macros forward information to tarch::instrumentation::Log. Log formats each line once and then dispatches it to the configured sinks. The tarch::instrumentation::CommandLineSink remains the default terminal sink. The same formatted line is also forwarded to tarch::instrumentation::FileSink, which writes Peano.log in the process working directory by default. Info, Warning, Error and Debug messages are forwarded to the file sink. The file sink flushes every write.

Warning and Error messages are highlighted only in the terminal sink and only if the target stream is an interactive terminal. Redirected terminal output and file output stay plain text without ANSI escape sequences. Stdout-style messages, such as Info and Debug, are written only by the global master rank. The same rank filter applies to the file sink. Stderr-style messages, such as Warning and Error, remain visible from every rank.

Debug logging has an additional runtime filter. The simplest way to configure it for a simulation run is the PEANO_LOG_DEBUG environment variable:

  • Unset, empty, 0, false, off or no: disable debug messages.
  • 1, true, on, yes, all or *: enable all debug messages.
  • Otherwise: comma separated list of scope prefixes. A debug message is emitted if its scope name starts with one of these prefixes, e.g. PEANO_LOG_DEBUG=exahype2::TimeStepping,tarch::mpi.

The same policy can be configured from C++ through tarch::instrumentation::Log::setDebug(bool), tarch::instrumentation::Log::enableDebugScopePrefix(...) and tarch::instrumentation::Log::clearDebugFilter().

CommandLineSink

This logger is the default terminal sink. It writes already formatted strings to stdout or stderr and does not coordinate other backends. The formatting and fan out are configured through tarch::instrumentation::Log. Please consult the header for details on the semantics of the arguments:

tarch::instrumentation::Log::setLogFormat(
" ",
true, false, false, true, true, true,
"myFancy.log"
);

The Log interface also allows you to override or disable the file sink. An empty file name disables file logging. The default is one shared file independent of the number of MPI ranks, written to the current working directory from which the executable is launched.

Assertions

Peano provides its own assertion format which is independent of C++ assertions. Assertions are offered through macros, and if you compile with PEANO_ASSERTIONS=0, then they are removed at compile time from your code.

Peano's assertions interlink with the logging, i.e. before they shut down a rank, they ensure that all logs are flushed. Furthermore, they provide a few convenient variations that

  1. Support numerical "equality" checks,
  2. Support the logging of parameters, and
  3. Support vector valued comparisons.

It is best to study the macros in tarch/Assertions.h to get an overview.
