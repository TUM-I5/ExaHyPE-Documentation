Action sets and traversal events

Action sets attach application behaviour to the events emitted by peano4::topology::TreeTraversal. The Python class peano4.solversteps.ActionSet provides one body for each generated callback, and an observer invokes its action sets in their configured order.

Traversal lifecycle

Every rank starts from one observer prototype. The topology manager creates a rank observer, and a parallel traversal creates an additional clone for each subtree task. Clones may execute concurrently and therefore keep their mutable state private. Static prepareTraversal() and unprepareTraversal() hooks run once per rank around the complete sweep.

Each observer clone receives beginTraversal() before its first event and endTraversal() after its last event. A face or vertex that two subtree tasks hold can therefore have one first-touch and last-touch lifecycle per task copy. The interface merge callbacks reconcile these copies with one sweep of lag.

Events

Event Semantics Ordering
prepareTraversal Prepares rank-wide action-set state. Runs before any observer instance is constructed.
beginTraversal Starts one rank or subtree-task observer. Precedes every entity event of that observer.
createVertex Initialises a newly created persistent vertex. Precedes its first touch.
createFace Initialises a newly created face. Follows creation of its adjacent vertices and precedes its first touch.
createCell Initialises a newly created cell. Follows creation of its adjacent faces and vertices and precedes its first touch.
touchHangingVertexFirstTime Presents a hanging vertex before adjacent fine-grid work. Precedes adjacent face and cell events.
touchHangingFaceFirstTime Presents a hanging face before its adjacent fine-grid cell. Follows the relevant vertex events.
touchVertexFirstTime Presents a persistent vertex for its first use by this observer. Precedes adjacent face and cell events.
touchFaceFirstTime Presents a face for its first use by this observer. Follows adjacent vertex first touches and precedes adjacent cell events.
touchCellFirstTime Enters a cell. Follows first touches of adjacent vertices and faces.
touchCellLastTime Leaves a cell after its descendants. Precedes last touches of adjacent faces and vertices.
touchFaceLastTime Presents a face after its adjacent local cells. Precedes destruction when the transition removes the face.
touchVertexLastTime Presents a persistent vertex after its adjacent local cells. Precedes destruction when the transition removes the vertex.
touchHangingFaceLastTime Finishes one hanging-face use. Follows the adjacent cell event.
touchHangingVertexLastTime Finishes one hanging-vertex use. Follows adjacent face and cell events.
destroyCell Releases data of a removed cell. Follows its last touch and precedes destruction of adjacent faces and vertices.
destroyFace Releases data of a removed face. Follows its last touch.
destroyVertex Releases data of a removed persistent vertex. Follows its last touch and adjacent destruction events.
endTraversal Finishes one observer clone. Follows every entity event of that observer.
unprepareTraversal Finalises rank-wide action-set state. Runs after every observer clone has been destroyed.

Creation and destruction callbacks occur during creational or regrid transition sweeps. Standing sweeps emit first-touch and last-touch events only.

Markers and data

Entity records do not carry their geometric or ownership context. Generated callbacks receive a marker that derives this information from the traversal event:

  • peano4::datamanagement::VertexMarker
  • peano4::datamanagement::FaceMarker
  • peano4::datamanagement::CellMarker

Markers provide coordinates, mesh width, selection within the adjacent entity set, hanging state, refinement state, and local ownership. Debug coordinates stored inside generated data records are diagnostic fields and are not an application interface.

Generated observers translate the event's pool slots into references to the cell, face, and vertex data used by an action set. Interface transfers call the generated merge routines with peano4::stacks::SendReceiveContext::InterRank or peano4::stacks::SendReceiveContext::IntraRank.

Coarse-grid data

Callbacks in the first level below a subtree-task root receive synthetic parent storage. Deeper callbacks receive the physical parent data of the next coarser level. An action set that requires the physical parent performs that operation away from the task boundary.

Action-set order

An algorithmic step maps to one generated peano4::grid::GridTraversalObserver. Its action sets are ordered by descend_invocation_order for events that descend into the tree. The reverse order is used where the generated observer unwinds the traversal. This order controls action sets that touch the same entity; it does not order independent subtree tasks.
