Particle interaction sets

Particle action sets build local and active particle sets while a spacetree traversal emits its cell callbacks. These sets are temporary views over the particle objects stored on adjacent vertices.

Local and active sets

The local set contains the particles associated with the persistent vertices of the current cell on its level. A particle can occur in the local sets of several adjacent cells because the adjacent cells hold the same vertex.

The active set contains the local set and particles inherited from coarser levels whose interaction region can reach the cell. It lets a fine particle interact with larger particles stored higher in the tree. The action set builds both views for the current callback; neither is persistent storage.

Updating a particle once

A cell kernel filters its local particles with the cell marker's containment test and a per-particle update marker. The action sets use CellHasUpdatedParticle for this purpose. Without the marker, a particle on a cell boundary can be updated by more than one adjacent cell.

A vertex callback sees each vertex set at one unique lifecycle point, but it does not receive the active sets of neighbouring vertices. Particle-particle interactions therefore normally run from cell callbacks.

Interaction types

Multilevel interactions compare a local particle with the active coarse-level particles. When the active particle is coarser, the same callback also applies the reverse interaction: the coarse traversal cannot discover the fine particle from its own active set. The implementation is peano4.particles.UpdateParticle_MultiLevelInteraction_Sets.

Particle storage is described on Particle storage and exchange.

Movement and sorting

The sets are valid only while every particle is associated with the closest persistent vertex on the level selected for its search radius. Changing a position or search radius can break that invariant. The sorting action sets then lift the particle, move it, and drop it through refined levels over later sweeps.

An application waits until the sorting and sieve state has settled before it uses interaction sets that require the new associations. Particle sorting and mesh consistency describes this lifecycle, rank crossings, and tunnelling.

Parallel execution

Particle containers reject subtree-task replication, so a particle-bearing step traverses each rank serially. MPI exchange still maintains local and virtual copies at rank boundaries.
